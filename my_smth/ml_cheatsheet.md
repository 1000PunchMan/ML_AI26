## 0. Постановка задачи

- [ ] **Какую статистику я хочу предсказывать?** Функция потерь определяет, что выдаст модель:
  - нужна **сумма** (выручка, спрос, закупка) → **среднее** → MSE;
  - нужно **«типичное» значение** (цена квартиры, время ответа) → **медиана** → MAE;
  - ошибки в разные стороны стоят **по-разному** → **квантиль** → квантильная функция потерь. *(Л2 1:46–2:05)*
- [ ] **Что дороже: перепрогноз или недопрогноз?** Если недопрогноз (склад, нагрузка на сервер, медицина) → квантильная с $\tau > 0.5$. Если перепрогноз (бюджет) → $\tau < 0.5$. *(Л2 2:02; лектор перепутала направление, верно так)*
- [ ] **Нужен интервал, а не точка?** Две квантильные модели с $\tau = 0.1$ и $0.9$ дают интервал на ≈80% («доставка через 30–45 мин»). *(Л2 2:06)*
- [ ] **Метрика ≠ функция потерь.** Функция потерь нужна для обучения, метрика — для бизнеса. Выбрать метрику заранее. *(Л1)*

## 1. Первый взгляд на данные

- [ ] **Автоотчёт за минуту:** `ydata-profiling` / Sweetviz. Дальше копать вручную. *(Л2 0:13)*
- [ ] **Проверить типы:** числа, сохранённые строкой (`TotalCharges`), ID-колонки (`customerID`) — убрать из признаков. *(Л2 0:05)*
- [ ] **Дисбаланс классов** в классификации: посмотреть доли таргета. *(Л2 0:29)*
- [ ] **Пропуски / ошибки → NaN → заполнить** (медианой для чисел). *(Л1)*
- [ ] **«Выбросы» с боксплота не удалять автоматически.** Сначала понять: это опечатка или редкий, но реальный объект? *(Л1)*

## 2. Связи признаков (EDA)

- [ ] **Правильная мера связи под тип признаков:**
  - число–число, линейная связь → Пирсон;
  - число–число, монотонная связь / есть выбросы → Спирмен (ранги);
  - категория–категория → V Крамера (нормированный χ²);
  - всё со всем на одной шкале → **φK (phik)**. *(Л2 0:52–1:19)*
- [ ] **Корреляция ≈ 0 ≠ «связи нет».** Связь может быть немонотонной (горб, яма). **Всегда смотреть график «признак → таргет»** для важных признаков. *(Л2 0:58, 2:24)*
- [ ] **Связь немонотонная** (цена vs расстояние до МКАД) → для линейной модели: **бинаризовать + one-hot** или добавить $x^2$. Деревьям не нужно. *(Л2 2:24–2:28)*
- [ ] **Сильно скоррелированные признаки** (мультиколлинеарность) → для линейной модели оставить **один из пары**. Деревьям почти не мешает. *(Л2 1:23)*
- [ ] **Слабая связь с таргетом** → кандидат на удаление, но только после проверки на нелинейность (φK / график). *(Л2 1:23)*
- [ ] **Корреляция ≠ причинность.** Возможен третий фактор (конфаундер), обратная причинность, случайность. Причинность проверяют A/B-тестом. *(Л2 1:20)*
- [ ] **Итог EDA — текст с выводами**, а не набор графиков. *(Л2 1:23)*

## 3. Признаки (feature engineering)

- [ ] **Категории → one-hot.** Для линейной модели **на 1 столбец меньше**, чем категорий (иначе линейная зависимость с константным признаком). *(Л2 2:16–2:23)*
- [ ] **Много категорий** (1000 районов) → one-hot раздувает таблицу; искать другую кодировку. *(Л2 2:20)*
- [ ] **Сильные пары признаков → новый признак.** Линейная модель сама взаимодействия не находит. *(Л2 0:38–0:52)*
- [ ] **«Линейная» = линейная по весам.** С признаками можно делать что угодно: $x^2$, $\log x$, бины — модель останется линейной. *(Л2 2:28)*

## 4. Модель и обучение

- [ ] **Первая строка в таблице экспериментов — константный бейзлайн:** среднее (для MSE) или медиана (для MAE). Не бьём константу → что-то не так. $R^2 = 0$ ровно значит «не лучше среднего». *(Л2 1:47)*
- [ ] **Выбросы в таргете $y$, чистить нельзя** → MAE или **Huber** (квадрат около нуля + модуль дальше; $\delta$ — точка перехода). *(Л2 1:43, 2:07)*
- [ ] **MAE спасает от выбросов в $y$, но не в признаках $x$.** Выбросы в $x$ для линейной модели — рычаг. *(Л2 1:43)*
- [ ] **Правило «лосс → статистика» верно для любых моделей:** линейной, деревьев, бустинга, нейросетей — это параметр `loss` / `criterion` / `objective`. *(Л2 1:43)*
- [ ] **$y$ скошен вправо** (зарплаты, чеки, цены) → обучение на MSE даст прогнозы систематически **выше**, чем на MAE. Это не баг: они предсказывают разное. *(Л2 1:50)*

## 5. Оценка качества

- [ ] **Качество — только на данных, которые модель не видела** (отложенная выборка, кросс-валидация). *(Л1)*
- [ ] **Сравнивать модели по одной итоговой метрике**, даже если обучались на разных функциях потерь. *(Л2 1:59)*
