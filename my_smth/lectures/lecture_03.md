### 7 ключевых идей

1. **Метод максимального правдоподобия (ММП):** подбираем параметры так, чтобы *наблюдаемые данные* были максимально вероятны. Монетка: 7 орлов из 10 → $\hat p = 0.7$.
2. **Линейная регрессия = вероятностная модель:** $y = \langle w, x\rangle + \varepsilon$. Если шум **нормальный** → ММП **в точности равен минимизации MSE**. Это и есть ответ «Middle+» на вопрос «почему квадрат».
3. **Шум Лапласа** (тяжёлые хвосты, много выбросов) → ММП = минимизация **MAE**. **Huber** ↔ нормальный шум в центре + Лаплас на хвостах. Общий принцип: *loss = −log(плотность шума)*.
4. **Метрики регрессии:** RMSE и MAE — в единицах target, но не ограничены; **R²** — доля улучшения над константой: 1 = идеал, 0 = как среднее, < 0 = хуже константы.
5. **Относительные метрики** (MSLE, MAPE, SMAPE, WAPE) удобны, но **несимметричны** и имеют ловушки (нули, манипуляции). Выбирай **одну ведущую метрику** под бизнес-задачу.
6. **Baseline = константа** (`DummyRegressor`). Train R² 0.976 vs test 0.772 → **переобучение**; огромные веса — его симптом.
7. **Всё, что «обучается» (импутер, скейлер, энкодер, квантили), обучается только на train.** `Pipeline` гарантирует это автоматически и делает код читаемым.

### Главные формулы

**ММП для монетки:**
$$L(p) = C_{10}^{7}\, p^7 (1-p)^3 \to \max_p \quad\Rightarrow\quad \hat p = 0.7$$

**Правдоподобие выборки** (объекты независимы):
$$L(w) = \prod_{i=1}^{\ell} p(y_i \mid x_i, w) \to \max_w \quad\Longleftrightarrow\quad -\log L(w) = -\sum_{i=1}^{\ell}\log p(y_i \mid x_i, w) \to \min_w$$

**Нормальный шум → MSE:**
$$\varepsilon \sim \mathcal N(0, \sigma^2) \Rightarrow -\log L(w) = \frac{1}{2\sigma^2}\sum_{i}(y_i - \langle w, x_i\rangle)^2 + \text{const}$$

**Шум Лапласа → MAE:**
$$p(\varepsilon) = \frac{1}{2b}e^{-|\varepsilon|/b} \Rightarrow -\log L(w) = \frac1b\sum_i |y_i - \langle w, x_i\rangle| + \text{const}$$

**Метрики** ($\ell$ — объектов, $n$ — признаков):
$$\text{RMSE} = \sqrt{\tfrac1\ell\textstyle\sum (y_i - a_i)^2} \qquad R^2 = 1 - \frac{\sum (y_i - a_i)^2}{\sum (y_i - \bar y)^2} \qquad R^2_{adj} = 1 - (1 - R^2)\frac{\ell - 1}{\ell - n - 1}$$
$$\text{MSLE} = \tfrac1\ell\textstyle\sum\big(\log(a_i + 1) - \log(y_i + 1)\big)^2 \qquad \text{MAPE} = \tfrac1\ell\sum\frac{|y_i - a_i|}{|y_i|}$$
$$\text{SMAPE} = \tfrac1\ell\textstyle\sum\frac{|y_i - a_i|}{(|y_i| + |a_i|)/2} \qquad \text{WAPE} = \frac{\sum|y_i - a_i|}{\sum |y_i|}$$

### Словарик

| Термин | Что значит |
|---|---|
| Правдоподобие (likelihood) | Вероятность увидеть наши данные при данных параметрах — функция от параметров |
| ММП / MLE | Метод максимального правдоподобия: параметры = argmax правдоподобия |
| −log-правдоподобие (NLL) | Удобная форма: произведение → сумма, max → min |
| Шум $\varepsilon$ | Случайное отклонение $y$ от $\langle w, x\rangle$, среднее 0 |
| Гомо-/гетероскедастичность | Дисперсия шума постоянна / меняется с $x$ |
| Тяжёлые хвосты | Далёкие от среднего значения встречаются заметно чаще, чем у нормального |
| Распределение Лапласа | «Двусторонняя экспонента», острый пик + тяжёлые хвосты |
| Выброс | Объект, не похожий на остальные **и** на другие выбросы |
| Baseline | Простейшая модель для сравнения; в регрессии — константа (`DummyRegressor`) |
| R² / adjusted R² | Доля улучшения над константой / с поправкой на число признаков |
| MSLE / RMSLE | Ошибка в логарифмах — «по порядку величины» |
| MAPE / SMAPE / WAPE | Процентные ошибки (по объекту / «симметризованная» / взвешенная) |
| Ведущая метрика | Одна главная метрика задачи, по которой принимают решения |
| Переобучение | Модель «запомнила» train: на train отлично, на test заметно хуже |
| `downcast`, `category` | Типы pandas, экономящие память без потери информации |
| Feature engineering | Создание новых признаков: $x^2$, $1/x$, бины, произведения |
| `PolynomialFeatures` | Все произведения признаков до заданной степени |
| Data leakage (утечка) | Информация из test попала в обучение → завышенная оценка качества |
| `Pipeline`, `ColumnTransformer` | Цепочка шагов с единым fit/predict; разные шаги для разных колонок |

### ⚠️ Нюансы, где лектор оговорилась или упростила

- **Числа для MSLE (1:50).** В записи слышится «0,07», но это оговорка или ошибка распознавания речи: на слайде (стр. 40) верно — факт 100, прогноз 50 → **0.47**, прогноз 150 → **0.16**. Занижение штрафуется примерно в 3 раза сильнее.
- **«Ошибка в категориях drive-wheels» (2:16).** Там значения `rwd`, `fwd`, `4wd` — задний, передний и **полный** привод. Опечатки нет, `4wd` — легитимная категория. (Мысль «проверяйте категории на опечатки» при этом правильная.)
- **«R² может только вырасти при добавлении признаков» (1:43).** Верно **на обучающей выборке**. На тесте R² от мусорных признаков, наоборот, **падает** (переобучение) — проверено на графике в расширенном конспекте. Adjusted R² как раз штрафует за лишние признаки.
- **«С пайплайном мы точно не переобучились, потому что не заглядывали в тест» (2:51).** Pipeline защищает от **утечки данных** (оценка на test перестаёт быть завышенной), а не от **переобучения** (разрыв train ≫ test). Это разные проблемы; с переобучением борются регуляризацией, отбором признаков и т.д.
- **«Ранг матрицы 60 из 65» (2:30).** Это ранг **обучающей части** (`Xtrain`). У полной матрицы ранг 62. Суть та же: даже после `drop_first` в признаках осталась линейная зависимость.
- **MAPE «ограничена единичкой» (1:52)** — лектор сразу поправилась: сверху MAPE **не ограничена** (при перепрогнозе может быть 500%), а при недопрогнозе (неотрицательный прогноз) не превышает 100%.

## 4. Где это в проде

- **«Loss = −log правдоподобия»** — это общий язык всего ML: логистическая регрессия (будет дальше) и **LLM** обучаются минимизацией NLL (кросс-энтропия = −log вероятности правильного следующего токена). Понимание ММП — ключ к пониманию лоссов в deep learning.
- **Выбор loss по распределению ошибок:** смотрим на гистограмму остатков на валидации — если хвосты тяжёлые, пробуем MAE/Huber.
- **Метрики в бизнесе:** RMSE/MAE для инженеров, **MAPE/WAPE** — для менеджеров («ошибаемся в среднем на 12%»). В прогнозе спроса (ритейл) стандарт — **WAPE**, т.к. MAPE взрывается на товарах с нулевыми продажами.
- **Одна ведущая метрика** — договорённость с бизнесом до начала экспериментов. Иначе невозможно решить, «стало лучше или хуже».
- **`DummyRegressor`** — первая строка любого отчёта об экспериментах.
- **Pipeline** — то, что реально уходит в прод: один объект (`joblib.dump(pipe)`), который принимает сырые данные и выдаёт прогноз. Без пайплайна препроцессинг в проде легко рассинхронизировать с обучением.
- **`category` + `downcast`** — бесплатная экономия памяти в 5–10 раз на больших таблицах.

## 5. Самопроверка

<details><summary>1. Монетку бросили 10 раз, 7 орлов. Найди p методом максимального правдоподобия (через производную).</summary>

$\log L(p) = \text{const} + 7\log p + 3\log(1-p)$. Производная: $\frac7p - \frac{3}{1-p} = 0 \Rightarrow 7(1-p) = 3p \Rightarrow p = 0.7$.
</details>

<details><summary>2. Зачем брать логарифм правдоподобия и ставить минус? Не испортит ли это ответ?</summary>

Логарифм монотонный → точка максимума та же. Зато произведение превращается в сумму, а экспоненты исчезают. Минус превращает задачу максимизации в минимизацию (как привычно для loss).
</details>

<details><summary>3. Выведи, почему при нормальном шуме ММП = минимизация MSE.</summary>

$p(y_i|x_i,w) = \frac{1}{\sigma\sqrt{2\pi}}\exp\left(-\frac{(y_i - \langle w,x_i\rangle)^2}{2\sigma^2}\right)$. $-\log L = \ell\log(\sigma\sqrt{2\pi}) + \frac{1}{2\sigma^2}\sum(y_i - \langle w,x_i\rangle)^2$. Первое слагаемое не зависит от $w$, множитель $\frac{1}{2\sigma^2} > 0$ не меняет точку минимума → минимизируем $\sum(y_i - \langle w, x_i\rangle)^2$.
</details>

<details><summary>4. Что такое гетероскедастичность и почему она мешает?</summary>

Разброс шума меняется с $x$ (например, растёт). Нарушено предположение «σ = const». MSE одинаково взвешивает все точки, и шумная область сильнее влияет на решение; оценки становятся менее точными, а интервалы неопределённости — неверными.
</details>

<details><summary>5. Почему много выбросов → MAE? Свяжи с хвостами распределений.</summary>

У нормального распределения за 3σ лишь 0.27% точек, за 4σ — почти ничего, т.е. выбросов «не бывает». Если их заметно много — шум ближе к распределению с тяжёлыми хвостами, например Лапласу (за 3σ ≈1.4%, за 4σ ≈0.35%). ММП для Лапласа даёт $\sum|y_i - a_i|$ → MAE.
</details>

<details><summary>6. Какому предположению о шуме соответствует Huber loss?</summary>

Маленькие ошибки распределены нормально (квадрат в центре), большие — как у Лапласа (модуль на хвостах).
</details>

<details><summary>7. Чем выброс отличается от маленького кластера и от шума?</summary>

Выбросы далеко от всех и не похожи друг на друга. Маленькая плотная группа похожих объектов (элитное жильё) — не выбросы, а отдельный кластер / второй пик. Шум — небольшие отклонения от закономерности у всех объектов.
</details>

<details><summary>8. y = [2, 4, 6], прогноз a = [3, 4, 5]. Посчитай R².</summary>

$\bar y = 4$, $SS_{tot} = 4 + 0 + 4 = 8$, $SS_{res} = 1 + 0 + 1 = 2$, $R^2 = 1 - 2/8 = 0.75$.
</details>

<details><summary>9. Какие значения может принимать R²? Что значит R² = 0 и R² < 0? Почему у константы на test R² = −0.31?</summary>

$(-\infty, 1]$. 0 — модель не лучше предсказания средним; < 0 — хуже. Константа обучена на train (среднее train), а на test своё среднее → она хуже «идеального среднего test» → R² < 0.
</details>

<details><summary>10. Зачем adjusted R²?</summary>

Обычный R² на train не уменьшается при добавлении любых (даже мусорных) признаков — модель может дать им нулевые веса. Adjusted R² штрафует за число признаков $n$; поправка важна при небольшом $\ell$.
</details>

<details><summary>11. Когда нужна MSLE? Какие у неё ограничения?</summary>

Когда важна ошибка «по порядку» (10 млн vs 10.1 млн — почти не ошибка). Только для $y \ge 0$ (+1 спасает от $\log 0$). Несимметрична: при факте 100 прогноз 50 штрафуется ≈0.47, а 150 — ≈0.16 → занижение наказывается сильнее.
</details>

<details><summary>12. Прогноз 20. Факт 10 и факт 30 — какой вклад в MAPE? В чём ещё проблемы MAPE?</summary>

$|10 - 20|/10 = 100\%$, $|30 - 20|/30 = 33\%$ — одинаковая ошибка ±10, разный штраф (делим на факт). Плюс деление на 0/малые $y$, и MAPE не ограничена сверху.
</details>

<details><summary>13. Почему SMAPE лучше не использовать, а WAPE часто предпочитают MAPE?</summary>

В знаменателе SMAPE стоит прогноз, поэтому завышение штрафуется слабее такого же занижения (факт 100: прогноз 150 → 0.40, прогноз 50 → 0.67) — модели выгодно завышать; симметрии нет. WAPE = $\sum|y - a| / \sum|y|$: делим на общую сумму, так что отдельные нули в $y$ не ломают метрику.
</details>

<details><summary>14. Зачем выбирать одну ведущую метрику?</summary>

Метрики не синхронизированы: одна растёт, другая падает. Без ведущей метрики нельзя решить, стала ли модель лучше. Ведущая метрика должна отражать бизнес-запрос.
</details>

<details><summary>15. Train R² = 0.976, test R² = 0.772, веса от 0 до 43 000. Диагноз?</summary>

Переобучение: модель почти идеально подогналась под train и хуже обобщает. Огромные веса — дополнительный симптом (плюс линейная зависимость в признаках: ранг < числа столбцов). Лечение — регуляризация (следующая неделя).
</details>

<details><summary>16. y = 2·x1 + 3·x2² + шум. Почему LinearRegression на (x1, x2) работает плохо и как помочь, оставаясь в линейной модели?</summary>

Зависимость от $x_2$ немонотонная (парабола), прямая её не поймает. Помогают бины $x_2$ + one-hot или `PolynomialFeatures(2)` (добавит $x_2^2$). Модель остаётся линейной — по весам.
</details>

<details><summary>17. Что такое data leakage и как Pipeline его предотвращает?</summary>

Утечка — когда при обучении используется информация из test (например, среднее для импутации или min/max для скейлера посчитаны по всем данным) → оценка на test завышена. Pipeline делает `fit` всех шагов только на train, а на test — только `transform`/`predict`. Его можно целиком передать в `cross_val_score`.
</details>
