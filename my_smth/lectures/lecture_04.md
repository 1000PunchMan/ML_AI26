### 7 ключевых идей

1. **Переобучение** = хорошо на train, заметно хуже на test. **Недообучение** = плохо везде. Переобучение встречается чаще.
2. **Большие веса разных знаков — симптом переобучения.** Одна из причин — **линейная зависимость** признаков: если $\langle v, x\rangle = 0$, то веса $w$ и $w + \alpha v$ дают одинаковый прогноз, и решений бесконечно много.
3. **Регуляризация** — добавляем к потерям штраф за размер весов: $Q(w) + \alpha R(w)$. Свободный член $w_0$ не штрафуем. Работает с любой функцией потерь.
4. **L2 (Ridge)** сжимает все веса, но не до нуля, и делает $X^TX + \alpha I$ всегда обратимой. **L1 (Lasso)** зануляет часть весов — это автоматический отбор признаков.
5. **$\alpha$ — гиперпараметр:** мало — переобучение остаётся, много — недообучение. Подбираем `GridSearchCV` на кросс-валидации, а не по test.
6. **One-hot** плох при тысячах категорий. **Счётчик** заменяет категорию средним таргета: один столбец вместо тысяч.
7. **Счётчик «подглядывает» в таргет** → утечка и переобучение, сильнее всего на редких категориях. Лечение: **сглаживание** к глобальному среднему и подсчёт **по фолдам** (`TargetEncoder` в sklearn).

### Главные формулы

**Регуляризованная функция потерь:**
$$Q_\alpha(w) = Q(w) + \alpha R(w),\qquad R_{L2}(w) = \sum_{j=1}^{d} w_j^2,\qquad R_{L1}(w) = \sum_{j=1}^{d} |w_j|$$

**Линейная зависимость → бесконечно много решений:**
$$\langle v, x\rangle = 0 \ \Rightarrow\ \langle w + \alpha v,\ x\rangle = \langle w, x\rangle$$

**Ridge, аналитическое решение:**
$$w = (X^TX + \alpha I)^{-1}X^Ty$$

**L1 как задача с ограничением** (геометрия «ромба»):
$$Q(w) + \alpha\|w\|_1 \to \min \quad\Longleftrightarrow\quad Q(w) \to \min,\ \ \|w\|_1 \le C$$

**Одномерная интуиция** ($w_0$ — вес без регуляризации):
$$\text{L2: } w^* = \frac{w_0}{1+\alpha} \qquad\qquad \text{L1: } w^* = \text{sign}(w_0)\max\big(|w_0| - \tfrac\alpha2,\ 0\big)$$

**Счётчик и счётчик со сглаживанием:**
$$\text{mean\_target}(u) = \frac{\sum_{i:\, f(x_i) = u} y_i}{\#\{i: f(x_i) = u\}} \qquad\qquad \text{код} = \frac{\text{mean\_target}\cdot n_{rows} + \text{global\_mean}\cdot\alpha}{n_{rows} + \alpha}$$

### Словарик

| Термин | Что значит |
|---|---|
| Недообучение (underfitting) | Модель проще закономерности: плохо и на train, и на test |

| L1 / Lasso | Штраф $\sum \lvert w_j\rvert$; зануляет веса |
| L2 / Ridge (гребневая регрессия) | Штраф $\sum w_j^2$; сжимает веса |
| Коэффициент регуляризации $\alpha$ | Сила штрафа |
| Разреженная модель | Часть весов ровно 0 |
| Линии уровня | Точки, где функция потерь одинакова (эллипсы вокруг минимума) |
| Параметр модели | Число, которое находит `fit` (веса) |
| Гиперпараметр | Настройка, которую задаём мы до `fit` ($\alpha$) |
| `GridSearchCV` | Перебор сетки гиперпараметров с оценкой на кросс-валидации |
| Фолд | Одна из $k$ частей данных в кросс-валидации |
| One-hot encoding | Категория → $m$ бинарных столбцов |
| Label encoding | Категория → номер; ложный порядок для линейной модели |
| Счётчик / mean target encoding | Категория → среднее таргета в ней |
| Глобальное среднее | Среднее таргета по всем данным |
| Сглаживание | Подтягивание кодов маленьких категорий к глобальному среднему |
| Утечка таргета (target leakage) | В признак попала информация об ответе |

### ⚠️ Нюансы, где лектор оговорилась или упростила

- **«При больших альфа начинается уже переобучение» (1:20).** Оговорка: при слишком большом $\alpha$ начинается **недообучение**. Это видно и по её следующей фразе («не прийти в область недообучения»), и по семинару: при $\alpha = 10$ Lasso обнулила все веса и предсказывает константу.
- **«В трёхмерном пространстве — трёхмерный кубик» (0:46).** Для L1 в трёх измерениях область $|w_1| + |w_2| + |w_3| \le C$ — **октаэдр** (две склеенные пирамиды) с вершинами на осях. Кубик — это область $\max|w_j| \le C$. Суть та же: острые вершины лежат на осях.
- **Линии уровня MSE — «окружности» (0:37).** В общем случае это **эллипсы**; окружности получаются в частном случае. На вывод не влияет.
- **«65 линейных уравнений на 300 объектов» (1:16).** Точнее: 65 неизвестных (весов) и 331 уравнение (объект). Чем больше неизвестных на одно уравнение, тем легче подогнать шум.
- **«LASSO и RIDGE работают с любыми функциями потерь» (1:21).** Регуляризация — да, с любыми. Но классы `Lasso` и `Ridge` в sklearn — это только MSE. L1/L2 с другой функцией потерь: `SGDRegressor(loss=..., penalty='l1')`, `HuberRegressor(alpha=...)` (L2), `LogisticRegression(penalty=...)`.
- **Подбор $\alpha$ в таблице семинара** идёт по test MSE. Для иллюстрации нормально, но в работе $\alpha$ выбирают на кросс-валидации, иначе test перестаёт быть честной оценкой. Лектор это и говорит (1:26), и вывод в ноутбуке тоже.
- **`GridSearchCV` в ноутбуке запущен на 10 исходных признаках**, а не на 65. Поэтому он не улучшил модель (3110 против 3092). На 65 признаках тот же поиск даёт test MSE 3065 против 3790 без регуляризации. Подпись «Huber» в выводе — остаток кода, лектор это заметила (1:29).
- **В данных о диабете есть точная линейная зависимость** — это подтверждает рассказ про большие веса: `sex` бинарный, поэтому $\text{sex}^2 = 0.002262 + 0.006038\cdot\text{sex}$.

## 4. Где это в проде

- **L2 и weight decay в нейросетях.** Weight decay — на каждом шаге обучения веса немного уменьшаются. При обычном градиентном спуске это ровно L2-штраф $\alpha\sum w^2$; в оптимизаторе AdamW, которым обучают большинство сетей, включая LLM, — его близкий «развязанный» вариант. Идея «штрафуем большие веса, чтобы не переобучиться» — из этой лекции.
- **Ridge — безопасный выбор по умолчанию** для линейной модели на многих признаках. **Lasso** — когда нужна компактная модель или отбор признаков. **ElasticNet** = L1 + L2 одновременно; полезен, когда признаки сгруппированы и коррелируют (Lasso из группы похожих признаков выбирает один почти случайно).
- **Перед Ridge/Lasso признаки масштабируют** (`StandardScaler` в `Pipeline`): штраф одинаков для всех весов, и без масштабирования признак в мелких единицах наказывается сильнее.
- **Высококардинальные категории** — `user_id`, `merchant_id`, город, товар, домен — встречаются в антифроде, рекламе, рекомендациях. Для них target encoding (`sklearn.preprocessing.TargetEncoder`), в CatBoost встроены «упорядоченные» счётчики (близко к expanding mean). В нейросетях вместо счётчиков обучают **эмбеддинги** категорий.
- **Подбор гиперпараметров:** `GridSearchCV` для 1–2 гиперпараметров. Когда их много — `RandomizedSearchCV` или Optuna. Всегда внутри `Pipeline`, чтобы предобработка не подглядывала в валидационные фолды.
- **Утечка таргета — частая причина «модель отлично работала на валидации и провалилась в проде».** Любой признак, посчитанный по таргету, считают по фолдам или по данным строго из прошлого.

## 5. Самопроверка

<details><summary>1. Train MSE 0.025, test MSE 30. Train MSE 0.13, test MSE 0.13. Поставь диагнозы.</summary>

Первое — переобучение: на train почти идеально, на новых данных в разы хуже. Второе — либо норма, либо недообучение: зависит от того, насколько 0.13 плохо для задачи (сравни с константой или с $R^2$).
</details>

<details><summary>2. Почему огромные веса разных знаков — симптом переобучения? Дай два объяснения.</summary>

1) Огромный вес значит, что крошечное изменение признака сильно меняет прогноз; так ведёт себя модель, подогнанная под шум. 2) При линейной зависимости ($\langle v, x\rangle = 0$) к весам можно прибавить $\alpha v$ с любым $\alpha$, не меняя прогноза, поэтому решения могут быть сколь угодно большими и с разными знаками.
</details>

<details><summary>3. x₃ = x₁ + x₂. Веса (1, 2, 0). Найди другие веса с тем же прогнозом и проверь на объекте (2, 3, 5).</summary>

$v = (1, 1, -1)$. Например, $(1, 2, 0) + 5v = (6, 7, -5)$: $6\cdot2 + 7\cdot3 - 5\cdot5 = 12 + 21 - 25 = 8$, как и $1\cdot2 + 2\cdot3 = 8$.
</details>

<details><summary>4. Запиши функцию потерь Ridge и Lasso. Почему w₀ не штрафуют?</summary>

$\frac1\ell\sum(\langle w, x_i\rangle - y_i)^2 + \alpha\sum_{j\ge1} w_j^2$ и то же с $\sum_{j\ge1}|w_j|$. $w_0$ задаёт общий уровень прогноза; если его сжимать к нулю, модель не сможет выдавать большие значения таргета.
</details>

<details><summary>5. Почему (XᵀX + αI)⁻¹ существует даже при одинаковых столбцах?</summary>

$v^T(X^TX + \alpha I)v = \|Xv\|^2 + \alpha\|v\|^2 > 0$ для любого $v \ne 0$ при $\alpha > 0$: матрица положительно определена, значит, обратима. Для двух столбцов $(1,2,3)$: $\det(X^TX) = 0$, а $\det(X^TX + \alpha I) = \alpha(28 + \alpha) > 0$.
</details>

<details><summary>6. Нарисуй и объясни, почему L1 зануляет веса, а L2 нет.</summary>

Линии уровня ошибки — эллипсы вокруг решения без регуляризации; область L1 — ромб с вершинами на осях, L2 — круг. Решение — точка касания. Ромб чаще касается вершиной (одна координата = 0), у круга углов нет. Если оба веса изначально большие, L1 тоже может коснуться стороной и ничего не занулить.
</details>

<details><summary>7. α = 1, вес без регуляризации w₀ = 0.3 и w₀ = 2. Что сделают L1 и L2?</summary>

L2: $w_0/(1+\alpha)$ → 0.15 и 1.0. L1: $\max(|w_0| - 0.5, 0)$ → **0** и 1.5. L1 вычитает константу и обнуляет маленькие веса, L2 делит и до нуля не доводит; большой вес L1 сжимает слабее.
</details>

<details><summary>8. Что будет при α → 0 и при α → ∞? Как выглядит график test MSE от α?</summary>

$\alpha \to 0$ — обычная регрессия, переобучение остаётся. $\alpha \to \infty$ — все веса → 0, прогноз = константа, недообучение. Test MSE от $\alpha$ — «яма»: сначала падает, потом растёт. Лучшее $\alpha$ — на дне.
</details>

<details><summary>9. Модель плоха и на train, и на test. Поможет ли регуляризация?</summary>

Нет. Это недообучение, а регуляризация делает модель ещё проще. Нужны новые признаки или более гибкая модель.
</details>

<details><summary>10. Чем параметр отличается от гиперпараметра? Что делает GridSearchCV и сколько обучений при 7 значениях α и cv=3?</summary>

Параметры (веса) находит `fit`, гиперпараметры ($\alpha$) задаём мы до обучения. `GridSearchCV` для каждого значения сетки считает качество на кросс-валидации, выбирает лучшее и переобучает модель на всём train. $7 \times 3 = 21$ обучение + 1 финальное.
</details>

<details><summary>11. Почему нельзя подбирать α по test?</summary>

Тогда мы выбираем $\alpha$, лучший именно для этого test, и оценка на нём становится оптимистичной. Test должен остаться для одной финальной проверки; $\alpha$ выбирают на кросс-валидации внутри train.
</details>

<details><summary>12. Почему для города с 10 000 значений не подходят one-hot и label encoding?</summary>

One-hot даст 10 000 почти пустых столбцов, а у редких городов мало объектов, чтобы выучить вес. Label encoding введёт ложный порядок: линейная модель будет считать «Тверь = 2 × Москва».
</details>

<details><summary>13. Закодируй счётчиком: Москва 2/5 вернули, Тверь 4/5, Клин 0/2. Затем со сглаживанием α = 2.</summary>

Без сглаживания: 0.4, 0.8, 0. Глобальное среднее $6/12 = 0.5$. С $\alpha = 2$: $(2 + 1)/7 \approx 0.43$, $(4 + 1)/7 \approx 0.71$, $(0 + 1)/4 = 0.25$.
</details>

<details><summary>14. В чём утечка у счётчиков и почему она сильнее на редких категориях?</summary>

Признак посчитан по таргету тех же объектов, на которых модель учится, — в признаке сидит ответ. В маленькой категории среднее почти равно таргету конкретных объектов (Клин: 2 клиента → код 0 → «всегда 0»), и модель выучивает шум. В большой категории среднее устойчиво.
</details>

<details><summary>15. Как кодировать счётчиком по кросс-валидации? Как кодировать test?</summary>

Делим train на $k$ фолдов; каждый фолд кодируем средними, посчитанными по остальным фолдам; склеиваем. Test кодируем средними по всему train. В sklearn: `TargetEncoder().fit_transform(X_train, y_train)` и `.transform(X_test)`.
</details>

<details><summary>16. На бриллиантах one-hot дал RMSE 1131, счётчики — 1289. Почему? У огранки Ideal самая низкая средняя цена — значит, огранка снижает цену?</summary>

Категорий всего 5–8: one-hot видит каждую отдельно, а счётчик сжимает в одно число и теряет информацию. Про Ideal: нет, это смешение с размером — Ideal в среднем 0.70 карата против 1.05 у Fair. Счётчик видит только среднее по категории, без учёта других признаков.
</details>

### Открытые вопросы

- Регуляризация в классификации → логистическая регрессия.
